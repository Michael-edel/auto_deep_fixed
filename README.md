# auto_deep_fixed

Система обработки PDF счетов и других документов с использованием OpenAI API.

## Возможности

- Обработка PDF, JPG, PNG и других форматов документов
- Кэширование результатов по SHA256 хешу файлов
- Кэширование по страницам для многостраничных PDF
- Дедупликация файлов в рамках одного запуска
- Параллельная обработка файлов
- Ограничение одновременных запросов к OpenAI
- Троттлинг запросов для предотвращения 429 ошибок
- Автоматический retry с экспоненциальным backoff при rate limit
- FastAPI сервис для обработки документов через API
- Статистика обработки и биллинг

## Установка

```bash
pip install -r requirements.txt
```

## Конфигурация

Создайте файл `.env` с настройками:

```env
# OpenAI API
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

# Параллелизм
MAX_WORKERS=3                    # Количество параллельных потоков для обработки файлов
MAX_OPENAI_CONCURRENCY=2         # Максимальное количество одновременных запросов к OpenAI

# Троттлинг и retry
OPENAI_MIN_INTERVAL_SEC=0.7      # Минимальный интервал между запросами к OpenAI (секунды)
OPENAI_MAX_RETRIES=5             # Максимальное количество повторов при 429 ошибке

# Цены для биллинга
PRICE_PER_1K_IN=0.15             # Цена за 1K входных токенов в USD
PRICE_PER_1K_OUT=0.60            # Цена за 1K выходных токенов в USD

# База данных
DB_PATH=inventory.db
```

## Использование

### CLI (командная строка)

```bash
# Обработка одного файла
python main.py invoice.pdf

# Обработка папки с файлами
python main.py invoices/

# С указанием выходной папки
python main.py invoices/ --out results/
```

### FastAPI сервис

```bash
# Запуск сервера
uvicorn app.main:app --host 0.0.0.0 --port 8000

# Или через Docker
docker-compose up
```

API будет доступен на `http://localhost:8000`

Документация API: `http://localhost:8000/docs`

#### Endpoints

- `GET /health` - проверка здоровья сервиса
- `POST /v1/process` - обработка одного файла
- `POST /v1/process/batch` - обработка нескольких файлов
- `GET /v1/stats` - статистика обработки

## Параметры производительности

### MAX_WORKERS
Количество параллельных потоков для обработки файлов. Рекомендуется:
- Для небольшого количества файлов: 2-3
- Для больших батчей: 3-5

### MAX_OPENAI_CONCURRENCY
Максимальное количество одновременных запросов к OpenAI API. Рекомендуется:
- Для базовых аккаунтов: 2-3
- Для аккаунтов с повышенными лимитами: 3-5

### OPENAI_MIN_INTERVAL_SEC
Минимальный интервал между запросами к OpenAI (троттлинг). Помогает избежать 429 ошибок по TPM (tokens per minute).

Рекомендуемые значения:
- `0.5-0.7` - для базовых аккаунтов (200K TPM)
- `0.3-0.5` - для аккаунтов с повышенными лимитами (500K+ TPM)

### OPENAI_MAX_RETRIES
Количество повторов при получении 429 ошибки. При каждом повторе используется экспоненциальный backoff с jitter.

Рекомендуется: `5` (по умолчанию)

## Кэширование

Система использует двухуровневое кэширование:

1. **Кэш файлов** (`out/cache/<sha256>.json`) - полный результат обработки файла
2. **Кэш страниц** (`out/cache_pages/<sha256>_p<page>.json`) - результат обработки отдельной страницы PDF

При повторной обработке того же файла результат берется из кэша без обращения к OpenAI.

## Обработка ошибок

### Rate Limit (429)
При превышении лимита запросов система:
1. Автоматически повторяет запрос с экспоненциальным backoff
2. Использует `retry_after` из ответа OpenAI если доступно
3. После исчерпания всех попыток возвращает ошибку `RATE_LIMIT`

В batch-обработке документы с ошибкой rate limit помечаются как `error: "RATE_LIMIT"`, но обработка остальных файлов продолжается.

## Статистика

После обработки выводится статистика:
```
📊 Stats: files=10 | cache_hit=5 | cache_miss=5 | duplicates_reused=2 | openai_requests=15 | time=45.2s
```

- `files` - всего файлов
- `cache_hit` - попаданий в кэш
- `cache_miss` - промахов кэша
- `duplicates_reused` - переиспользованных дубликатов
- `openai_requests` - реальных HTTP запросов к OpenAI
- `time` - время выполнения в секундах
